    AICenter 未来开发计划

    本文档基于对 Serpmind（企业级多渠道 AI Agent 框架）架构总结文档与 AICenter（大模型 AI 服务中心）项目的深度对比分析，梳理两者功能差异、AICenter 缺失的功能模块，并按重要程度规划未来开发路线。

    一、项目定位与架构对比

    1.1 项目定位差异

    维度AICenterSerpmind
    定位AI 应用开发与管理平台（B 端管理后台）企业级多渠道 AI Agent 框架（Agent 引擎）
    核心能力知识库 RAG + 可视化 Agent 编排 + 模型管理多渠道接入 + 长期记忆 + 自主 Agent 循环
    交互方式Web 前端（React + Ant Design）20+ 聊天平台 + OpenAI 兼容 API
    架构风格FastAPI 同步 + Peewee ORM + MySQLasyncio 异步 + Pydantic v2 + 文件持久化
    Agent 模型可视化 DSL 编排（组件拖拽连线）AgentLoop 主循环 + 工具自主调用
    记忆机制无独立长期记忆系统Consolidator + AutoCompact + Dream 三机制
    安全策略基础用户/角色管理RBAC + SSRF 防护 + 限流 + 审计 + 工作区隔离

    1.2 架构设计差异

    AICenter 架构特点

    • 管理后台导向：完整的 CRUD 管理界面，面向运维和业务人员
    • 可视化编排：Agent 通过 DSL 组件拖拽编排（begin → categorize → retrieval → generate → answer）
    • RAG 为核心：DeepDoc 文档解析 + Elasticsearch 向量检索 + 多种切片策略
    • 同步架构：基于 FastAPI + Uvicorn，多 worker 进程
    • 关系型存储：MySQL 持久化，Redis 缓存，ES 检索

    Serpmind 架构特点

    • Agent 引擎导向：以 AgentLoop 为核心，面向自主任务执行
    • 事件驱动：MessageBus 双 asyncio.Queue 解耦渠道与 Agent
    • 多进程隔离：每个 Agent 独立 Worker 进程，崩溃隔离
    • 文件持久化：JSONL 会话存储 + Markdown 记忆文件 + Git 版本控制
    • 异步优先：全链路 asyncio，支持高并发流式输出

    2.2 AICenter 独有优势

    以下是 AICenter 相比 Serpmind 已具备且更优 的能力，未来开发中应继续保持和强化：

    1. 知识库 RAG 体系：DeepDoc 文档解析（PDF/Word/Excel/PPT/HTML/Markdown）、多种切片策略（naive/book/qa/table/resume 等）、Elasticsearch 向量检索 + 全文搜索、知识库转工具（react 模式）、智能知识提取
    2. 可视化 Agent 编排：DSL 组件拖拽编排，支持 30+ 组件节点（categorize/switch/iteration/concentrator/retrieval/generate 等），适合非开发人员构建复杂流程
    3. 统一模型管理：支持文本生成、图像理解、语音识别、语音合成、Embedding、Rerank 多种模型类型，UI 化配置
    4. 多数据源管理：MySQL、PostgreSQL、Oracle、SQL Server、RustFS、S3、Tavily 等 7+ 种数据源连接器
    5. Web 管理后台：React + Ant Design 完整前端，机器人/知识库/模型/提示词/用户全管理
    6. 流式重连机制：基于 Redis 的流式数据存储，切换对话或刷新页面后可继续输出
    7. 插件集成：支持第三方插件嵌入 HTML 聊天界面，API Key 认证
    8. Docker 完整部署：docker-compose 一键部署完整环境

    三、缺失功能详细分析

    3.1 长期记忆系统（完全缺失）

    这是 AICenter 与 Serpmind 最大的差距。Serpmind 拥有三套协同的记忆机制，而 AICenter 目前仅有聊天记录的数据库存储，无任何长期记忆能力。

    Serpmind 三大记忆机制

    机制触发时机职责存储
    Consolidator每次用户消息前同步检查Token 超限时 LLM 总结旧消息history.jsonl（追加摘要）
    AutoCompact会话空闲超时（后台异步）归档空闲会话，只留最近 8 条history.jsonl + session 摘要
    DreamCron 定时（每 2 小时）分析历史摘要，编辑长期记忆文件MEMORY.md / SOUL.md / USER.md

    AICenter 缺失内容

    • 长期记忆文件：无 MEMORY.md（项目知识/用户偏好/待办事项）、SOUL.md（Agent 人格）、USER.md（用户画像）
    • 历史摘要流：无 history.jsonl 追加式对话摘要
    • Dream 记忆整合器：无两阶段 Agent（Phase1 分析 + Phase2 编辑），无法自动整理和更新记忆
    • Git 版本控制：无记忆文件版本管理和回滚能力
    • Token 预算压缩：无 Consolidator 的 5 轮压缩机制
    • 空闲会话归档：无 AutoCompact 的后台压缩能力

    3.2 内置工具系统（严重缺失）

    AICenter 目前仅有 web_search 和 generate_ppt 两个内置工具，而 Serpmind 拥有 15+ 个功能完善的内置工具。

    工具对比

    工具AICenterSerpmind说明
    web_search有有双方均支持，基于 SearXNG
    web_fetch无有网页抓取（含重定向后 SSRF 防护）
    read_file无有读取文件（支持用户隔离边界检查）
    write_file无有写入文件
    edit_file无有编辑文件（字符串替换）
    list_dir无有列出目录
    glob无有Glob 模式文件搜索
    grep无有正则内容搜索
    exec无有Shell 命令执行（含 SSRF 检测）
    notebook_edit无有Jupyter Notebook 编辑
    ask_user无有向用户提问，中断循环等待回答
    spawn无有启动子 Agent 并行任务
    cron无有管理定时任务
    message无有发送消息到渠道
    my无有Agent 自我管理（读写 SOUL/USER 等）
    generate_ppt有无AICenter 独有：PPT 生成

    工具基础设施缺失

    • 工具授权网关：无 guard_tool_call 统一授权机制（工具白名单 + 参数级授权）
    • 工具作用域：无 is_tool_allowed 基于角色的工具白名单控制
    • 工具并发控制：无 read_only / concurrency_safe / exclusive 并发标记
    • 工具指标埋点：无工具调用的计数和延迟统计
    • SSRF 防护：web_search / web_fetch 无内网地址封堵和重定向校验

    3.3 安全策略体系（严重缺失）

    AICenter 仅有基础的用户/角色管理（is_admin 字段），缺乏完整的安全治理体系。

    缺失的安全能力

    安全能力AICenterSerpmind说明
    RBAC 角色权限仅 is_admin完善Serpmind 有 platform_admin/tenant_admin/user/webui 多角色
    多租户隔离无有Serpmind 支持 tenant_id + workspace_id 隔离
    工作区隔离无有Serpmind 有 immutable/project/memory 路径分区
    SSRF 防护无三层Serpmind 有 DNS 解析校验 + 重定向校验 + 命令内 URL 检测
    限流常量定义滑动窗口Serpmind 有 user/tenant/IP 三级限流
    审计日志无JSONLSerpmind 记录所有工具拒绝/队列拒绝决策
    安全指标无MetricsStoreSerpmind 有 tool.denied/tool.error/latency 等指标
    Agent 定义文件锁无有Serpmind 保护 SOUL/USER/AGENTS 等文件防篡改
    路径穿越拦截无有Serpmind 拦截 ../ 路径穿越攻击
    用户隔离无有Serpmind 阻止访问其他用户目录
    超级权限无有Serpmind 有 super_permission 绕过所有边界

    3.4 Agent 执行引擎（部分缺失）

    本项目的"Agent 执行引擎"即 ChatCoreService 聊天服务，已具备完整的对话主循环与开始/停止控制逻辑：

    • 对话主循环：_run_conversation_loop 实现"消息接收 → 上下文构建 → LLM 调用 → 工具执行 → 响应发送"完整循环
    • 开始逻辑：chat_stream 流式入口，包含 preprocess（预处理）→ execute（执行）→ postprocess（后置处理）三段式流程编排
    • 停止逻辑：ChatStopManager 单例管理停止状态，提供 request_stop（标记停止）、is_stop_requested（循环中检查停止标记）、clear_stop（清除标记）三个方法，GeneratorExit 时自动触发停止
    • 流式重连：基于 Redis 存储，刷新或切换会话后可继续输出

    但相比 Serpmind 的 AgentLoop，仍缺少以下增强能力：

    缺失的 Agent 引擎增强能力

    能力AICenterSerpmind说明
    上下文治理流水线无5层孤儿清理/补全/微压缩/Token预算/历史裁剪
    Mid-turn injection无有工具执行后注入新消息继续循环
    Checkpoint 恢复无有中断后可恢复部分上下文
    空响应重试无有最多 2 次空响应重试
    Length 恢复无有finish_reason=length 时追加继续提示
    子 Agent 管理DSL编排运行时spawnSerpmind 可运行时启动子 Agent 并行处理
    生命周期钩子无6个before_iteration/on_stream/before_execute_tools 等
    技能系统无SkillsLoaderSKILL.md 技能文件 + 渐进式披露

    3.5 自主性基础设施（完全缺失）

    缺失模块

    • CronService 定时任务：支持 at（一次性）、every（固定间隔）、cron（cron 表达式 + 时区）三种调度，用于 Dream 记忆整合、reminder 提醒
    • CommandRouter 命令路由：四层优先级分发（priority/exact/prefix/interceptors），支持 /stop、/restart、/status、/new、/history、/dream 等斜杠命令

    3.6 运行时调度（部分缺失）

    缺失的运行时能力

    • 多进程调度器：Dispatcher 每 Agent 一个独立 Worker 进程，崩溃隔离
    • TurnWorkerPool 轮次工作池：固定大小 worker 池，同会话串行、跨会话并发
    • AdmissionController 准入控制：背压（队列满时拒绝）+ 排队位置通知
    • AgentRestartOrchestrator 重启编排器：协调 agent 运行时重启与渠道热重载
    • MessageBus 事件总线：双 asyncio.Queue（inbound 有界 + outbound 无界）解耦渠道与 Agent

    3.7 OpenAI 兼容 API（部分缺失）

    AICenter 已实现完整的 OpenAI 兼容接口，包括 /v1/chat/completions（流式 SSE 与非流式）、/v1/models、Agent 路由、会话隔离、认证中间件（Bearer Token / api-key / x-api-key，localhost 豁免）等核心能力。相比 Serpmind 仍缺少以下增强能力：

    缺失的增强能力

    • 企业限流：按 user/tenant 维度 RPM 限流
    • 流式实现：asyncio.Queue + on_stream/on_stream_end 回调 → OpenAI SSE chunk
    • ask_user 交互：finish_reason 为 stop + buttons 字段携带选项

    四、未来开发计划

    根据功能重要程度、技术依赖关系和对核心竞争力的提升，将未来开发分为 4 个优先级阶段：

    P0
    核心基础能力
    P1
    安全与自主性
    P2
    生态扩展
    P3
    增强与优化

    4.1 P0 阶段：核心基础能力（最高优先级）

    目标：补齐 Agent 自主执行的核心基础设施，使 AICenter 从"编排工具"升级为"自主 Agent 平台"。

    P0-1. 上下文治理流水线 P0

    实现 Serpmind 的 5 层上下文治理，解决长对话 Token 超限问题

    • _drop_orphan_tool_results：删除无对应 tool_call 的孤儿工具结果
    • _backfill_missing_tool_results：为缺失 tool_result 的 tool_call 补充合成错误消息
    • _microcompact：将旧工具结果替换为一行摘要（保留最近 10 个原样）
    • _apply_tool_result_budget：对超长工具结果按 max_tool_result_chars 截断
    • _snip_history：Token 预算裁断，确保 user 角色开头
    • 容错设计：治理失败回退到只跑前两步，再失败用原始消息

    P0-2. 内置工具体系扩展 P0

    从 2 个工具扩展到 10+ 个，覆盖文件/搜索/Web/交互核心场景

    • 文件工具：read_file、write_file、edit_file、list_dir
    • 搜索工具：glob（文件搜索）、grep（内容搜索）
    • Web 工具：web_fetch（网页抓取，含内容提取）
    • 交互工具：ask_user（向用户提问，中断循环等待回答）
    • 工具基类增强：增加 read_only/concurrency_safe/exclusive 标记
    • 工具参数校验：完善 validate_params 和 cast_params 类型转换
    • 工具指标埋点：记录 tool.{name}.ok/error/latency_ms

    P0-3. 长期记忆系统 P0

    实现 Consolidator + AutoCompact 双机制，解决长对话记忆丢失问题

    • Consolidator：每次用户消息前同步检查 Token 预算，超限时 LLM 总结旧消息
    • 压缩配置：consolidation_ratio=0.5，最多 5 轮压缩
    • 摘要存储：会话级摘要表（替代 history.jsonl），记录 cursor/timestamp/content
    • AutoCompact：后台扫描空闲会话（TTL 过期），保留最近 8 条 + 摘要
    • 会话恢复：下次用户回来时注入压缩摘要为 runtime context
    • Token 估算：实现基于消息链的 Token 数估算

    P0-4. Agent 执行循环增强 P0

    基于现有 ChatCoreService 聊天循环（已具备开始/停止/流式重连），增加容错和恢复能力

    • 空响应重试：最多 2 次空响应重试
    • Length 恢复：finish_reason=length 时追加继续提示，最多 3 次
    • Checkpoint 机制：每个 iteration 发出 checkpoint，中断后可恢复
    • ask_user 中断恢复：检测未应答的 ask_user tool_call，用户回复填入 tool_result
    • Mid-turn injection：工具执行后检查 pending_queue，有新消息则注入

    4.2 P1 阶段：安全与自主性（高优先级）

    目标：建立完整的安全防护体系和自主执行能力，支撑企业级生产部署。

    P1-1. 安全策略体系 P1

    构建纵深防御的安全架构，从限流到工具授权全覆盖

    • RequestContext 安全上下文：user_id/tenant_id/role/workspace_id，基于 ContextVar 异步隔离
    • RBAC 角色权限：platform_admin/tenant_admin/user/webui 多角色
    • 工具授权网关：guard_tool_call 统一网关（工具白名单 + 参数级授权）
    • SSRF 防护：内网地址黑名单 + DNS 解析校验 + 重定向后校验 + 命令内 URL 检测
    • 滑动窗口限流：user/tenant/IP 三级 RPM 限流（基于 time.monotonic）
    • 审计日志：JSONL 记录所有工具拒绝/队列拒绝决策
    • 安全指标：MetricsStore 计数器 + 延迟统计
    • 路径穿越拦截：拦截 ../ 路径穿越攻击

    P1-2. Dream 长期记忆整合器 P1

    实现 Dream 两阶段 Agent，自动整理和更新长期记忆

    • 记忆文件体系：MEMORY.md（长期记忆）、SOUL.md（Agent 人格）、USER.md（用户画像）
    • Dream Phase 1：读取历史摘要未处理条目，LLM 分析产出报告
    • Dream Phase 2：AgentRunner 用 read_file/edit_file/write_file 编辑记忆文件
    • git-blame 年龄标注：超过 14 天的行标记 ← 30d
    • Dream cursor：跟踪已处理进度，每批最多 20 条
    • 版本控制：记忆文件变更支持 diff 查看和回滚

    P1-3. 定时任务服务 P1

    实现 CronService，支撑 Dream 记忆整合和用户提醒

    • 三种调度模式：at（一次性）、every（固定间隔）、cron（cron 表达式 + 时区）
    • 持久化存储：jobs.json + action.jsonl（操作日志）+ FileLock
    • 数据安全：损坏文件备份为 .corrupt-{ts}（保留 5 份），原子写入
    • 系统任务：Dream 记忆整合（每 2 小时）、reminder 提醒
    • 管理 API：创建/列表/删除定时任务接口

    P1-4. 命令路由系统 P1

    实现斜杠命令支持，增强用户交互控制能力

    • 四层优先级分发：priority（锁外）/ exact（锁内）/ prefix / interceptors
    • 内置命令：/stop（取消任务）、/new（清空会话）、/status（状态）、/history（历史）
    • 记忆命令：/dream（手动触发）、/dream-log（查看 diff）、/dream-restore（回滚）
    • 命令权限：基于角色控制命令可用性

    4.3 P2 阶段：生态扩展（中优先级）

    目标：扩展外部集成与生态兼容性，提升平台开放能力。

    P2-1. OpenAI 兼容 API 增强 P2

    OpenAI 兼容接口核心能力（/v1/chat/completions、/v1/models、Agent 路由、会话隔离、认证中间件）已实现，在此基础上增强企业级能力

    • 企业限流：按 user/tenant 维度 RPM 限流
    • ask_user 交互：buttons 字段携带选项，前端渲染按钮

    P2-2. 子 Agent 管理 P2

    支持运行时启动子 Agent 并行处理独立任务

    • SubagentManager：spawn(task, label, session_key) 启动子 Agent
    • 状态追踪：SubagentStatus（initializing → awaiting_tools → done/error）
    • 独立工具注册表：子 Agent 拥有独立工具集（不含 spawn 防递归）
    • 完成通知：通过消息总线向原会话发送完成通知
    • 并发控制：限制最大并发子 Agent 数量

    4.4 P3 阶段：增强与优化（较低优先级）

    目标：完善细节体验，提升系统稳定性和可维护性。

    P3-1. 技能系统 P3

    实现 SKILL.md 技能文件体系，教会 Agent 如何使用特定工具

    • SkillsLoader：技能发现（内置 + 工作区）+ YAML Frontmatter 解析
    • 渐进式披露：always:true 技能全文注入，其他仅注入摘要
    • 按需加载：Agent 通过 read_file 加载完整技能内容
    • 内置技能：weather、memory、summarize 等示例技能

    P3-2. 生命周期钩子 P3

    提供 Agent 执行全生命周期的扩展点

    • 6 个钩子：before_iteration/on_stream/on_stream_end/before_execute_tools/after_iteration/finalize_content
    • CompositeHook：聚合多个钩子，顺序调用，错误隔离
    • 插件化扩展：第三方可通过钩子注入自定义逻辑

    P3-3. 多进程调度优化 P3

    提升高并发场景下的稳定性

    • TurnWorkerPool：固定大小 worker 池，同会话串行、跨会话并发
    • AdmissionController：背压（队列满时拒绝）+ 排队位置通知
    • 多进程隔离：每 Agent 独立 Worker 进程（可选）
    • 重启编排：AgentRestartOrchestrator 协调重启与热重载

    P3-4. 多租户与工作区隔离 P3

    支持企业级多租户场景

    • 多租户：tenant_id 隔离，每租户独立用户/配置/数据
    • 工作区：workspace_id 隔离，immutable/project/memory 路径分区
    • 用户隔离：阻止访问其他用户目录
    • 超级权限：super_permission 绕过所有边界（运维场景）

    5.4 核心原则

    在开发过程中应遵循以下原则：

    1. 保持 AICenter 优势：知识库 RAG、可视化编排、模型管理、Web 后台等已有优势功能不能退化
    2. 渐进式增强：新功能与现有架构融合，不推翻重写，保证平滑过渡
    3. 配置驱动：安全策略、记忆机制等采用配置驱动，默认宽松，按需启用
    4. 复用现有基础设施：MySQL 持久化（替代 JSONL）、Redis 缓存、ES 检索等现有组件优先复用
    5. 代码风格统一：新代码遵循现有项目风格，重复代码提取为公共方法
